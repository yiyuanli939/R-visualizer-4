# 生产级大规模 R 代码：现状与设计

本文档记录 R Visualizer 面对"大文档 + 大数据"时的实测表现、已落地的优化，以及走向生产级的设计路线。

## 一、实测基线（2026-07）

压测脚本：`stress-trace.R`（本机 R 4.5 / 浏览器 webR wasm 双端）。

| 场景 | 结果（优化后） |
| --- | --- |
| 600 条语句的平铺大文档 | 本机 1.35s / JSON 169KB；wasm 3.6s，600 步全记录 |
| 156 行真实分析文档（回归/聚合/循环/卡方混合） | 本机 147ms / 85KB |
| 100 万行 data frame 建表 + 聚合 | 253ms；任意窗口分页 7ms |
| 5e5 数值大对象在循环里改 30 次 | 691ms / 904KB（真实变更，无法再省） |
| 200k 单元格 df 连续 100 次列变换（wasm） | 4.7s，101 步 |
| 折叠循环（150 次迭代）中途报错 | 正确记录错误步并终止 |
| 闭包/递归/S4/环境对象/list-column/rm() | 全部正确快照 |
| 用户自己用 capture.output / tryCatch / options | 不干扰追踪 |

**已落地的关键优化（本轮）：增量快照**。此前每步快照为环境里*所有*变量发条目（未变的发 `ref` 占位），600 变量 × 600 步 = 36 万条 → 7.6s / 4.9MB。现在 R 侧只发 added/changed 的预览 + removed 名单，未变对象用 `identical()`（同指针快速路径）跳过重新哈希；前端累积重建全景。复杂度从 O(变量数 × 步数) 降到 O(变更数)。

## 二、当前的防护机制（已实现）

- **步数预算**：全局 1000 步硬上限，超出后继续执行但停止记录（最终状态仍正确），UI 提示截断。
- **迭代折叠**：单循环完整记录前 100 次迭代，之后折叠为一步（"iterations 101…N folded"）。
- **预览窗口**：data frame 只序列化 50 行 × 60 列 + schema；单元格字符串截断 200 字符；stdout 每步截 40 行；`max.print=1000`。
- **按需分页**:大表更多行/列从活跃 R 会话按窗口取（百万行 7ms），不进快照。
- **大对象指纹采样**：>8MB 的对象用 dim + 首尾切片哈希，避免全量 digest。
- **步骤环境保留预算**：每步保留环境引用（R copy-on-write，未变对象零成本）用于历史分页，累计新增字节 >200MB 自动停止保留并降级到"仅最终环境分页"。
- **中断**：webR SharedArrayBuffer 通道支持 `interrupt()`，UI 有 Stop 按钮，防死循环锁死页面。

## 三、通往生产级的设计路线

### 3.1 大文档（数百上千行脚本）

1. **区间选择执行（最优先）**：像 RStudio 一样支持"只可视化选中区域/光标所在段落"。前置代码用一条 `eval(parse(...))` 快速执行不记录（fast-forward），只对选区做全粒度追踪。实现量小：`.tr_run(code, from_line, to_line)`，from 之前的表达式走 folded 路径即可。
2. **懒加载步骤详情**：JSON 里 steps 只带骨架（行号/种类/diff 名单），预览按 `.tr_step_detail(i)` 在用户拖到该步时再取。1000 步文档首包可 <50KB。目前 169KB/600 步尚可接受，此项在步数上限提高后变刚需。
3. **提高步数上限的前提**：步骤列表 UI 已虚拟化到滑块粒度；把 1000 上限做成设置项（1000/5000/10000），配合懒加载详情。
4. **`source()`/多文件支持**：拦截 `source()`，把被引文件也纳入行号映射（srcref 带 filename），编辑器多 tab。
5. **函数体步进（opt-in）**:定义时对用户函数体做同款 AST 插桩（机制已复用循环插桩），快照局部环境 + 调用栈展示。默认关，点函数名开。

### 3.2 大数据（百万行级、GB 级）

1. **内存天花板是 wasm 堆**（浏览器 tab 通常 2–4GB）。策略：
   - `object.size` 探测 + 在状态条常驻显示 R 内存占用（`gc()` 报告），接近上限时警告；
   - 步骤环境保留预算（已有）改为可配置，并在超限时自动 `gc()`。
2. **数据不进快照，只进窗口**：坚持"schema + 维度 + 窗口"原则（已落地）。任何新面板（如列统计摘要）都应按需向活跃会话查询，而不是进 trace。
3. **列摘要面板**（生产分析刚需）：对聚焦 df 按需计算每列 min/max/mean/NA 数/n_distinct（`.tr_col_stats(name)`），一次只算可视列。
4. **Arrow/Parquet 上传**：webR 有 arrow 的 wasm 版受限;先支持 `.rds`/`.csv.gz`（readr 原生），大文件上传走流式写 VFS（`FS.writeFile` 分块）。
5. **超大数据的正确姿势是抽样**：提供"用前 N 行试跑管道"一键开关（`slice_head(n=10000)` 注入到管道头），验证逻辑后再全量跑——这是把可视化工具用于生产数据的核心工作流。

### 3.3 长时运行与健壮性

1. **进度心跳**：`.tr_run` 每 N 步通过 webR 消息通道上报进度（当前用 captureR 同步阻塞拿不到中间态；可改为 R 侧 `cat` 特殊标记 + JS 端流式读取，或分批驱动）。
2. **分批驱动**：把顶层表达式分批（每批 ~50 条）多次调用 R，批间让出主线程 → UI 可显示"已执行 k/N 条"并随时中断，也自然支持懒加载。
3. **Worker 化**：webR 本就在 Worker 里；剩余的主线程重活（JSON.parse 大包、dataURL 转换）也可移到专用 Worker。
4. **包缓存**：webR 支持把已装包挂载到 IndexedDB（`mount` 选项）——二次访问免重新下载 tidyverse（~40MB），生产部署必开。另可用 `webr::mount()` 预打包镜像放 CDN。
5. **用户 `sink()` 边界**：用户代码里不配对的 `sink()` 会弹掉我们的捕获层（实测只产生一条警告，不崩）。生产上在每步后校验 `sink.number()` 并自动修复。

### 3.4 部署（Vercel）

- 纯静态输出（`next build` 全预渲染），wasm 资产 47MB 由 `prebuild` 拷贝，在 Vercel 构建期完成；COOP/COEP 响应头由 `next.config.ts` `headers()` 下发。
- 建议：`public/webr` 与包镜像走 Vercel CDN 长缓存（immutable 文件名已含版本）；开启上面的 IndexedDB 包缓存后，回访用户冷启动 <2s。
- 隐私红利：用户代码与数据全部留在浏览器，不经过服务器——对生产数据合规友好。

## 四、真实代码回放战报（2026-07，持续循环中）

**语料一：Kosuke Imai《Quantitative Social Science》官方仓库**（普林斯顿定量社科教材，7 章 × base/tidyverse 双版本 = 14 个脚本，170B–976 行，含文本挖掘、网络分析、bootstrap 模拟）：

- 14/14 端到端跑通，0 引擎崩溃；管道步最多单脚本 441 个；wordcloud/igraph/ggplot 图形全部捕获。
- 浏览器实测：646 行 `causality-tidy.R` + 9MB social.csv 等 6 个数据集上传（含子目录路径），243 步与本机 R 完全一致；qss 包装不上仅降级为警告，6 处 `data()` 错误被记录后继续执行到底。

**语料二：Scott Cunningham《Causal Inference: The Mixtape》**（58 个计量经济复现脚本：IV/DiD/RDD/PSM/合成控制等）：

- 58/58 无引擎崩溃，共 634 步、28 图；报错的 16 个脚本全部归因于缺 wasm 外专业包（Synth/MatchIt/rdrobust…）、片段顺序依赖或真实的 `select` 函数遮蔽（MASS/arm 覆盖 dplyr）。

**由真实代码驱动的机制/UI 改进（本轮已落地）**：

1. **出错后继续**（默认开）：教材含故意报错章节、复现脚本含过时 API 调用；现在错误逐条记录为红步，执行到底，状态条 "⚠ N 处错误——点击跳转" 逐个跳转。
2. **`%>%` 链的 `.` 代词绑定**：`df %>% mutate(yhat = predict(lm(y ~ x, .)))` 这类嵌套 `.`（magrittr 语义）此前报 `object '.' not found`，现按 magrittr 规则在链环求值环境中绑定 `.`。
3. **保留工作区**：复现代码普遍是"片段接力"（lmb_1…lmb_5 共享 lmb_data）；新开关让连续 Run 累积同一环境，且基线变量随结果下发（面板可见但不标"新增"）。
4. **最大步数可调**（1000/2000/5000）：4/14 教材脚本与多个模拟脚本天然超过 1000 步。
5. **装不上的包降级为警告**：不再拒绝整次运行，让 `library()` 在自己那步自然报错并继续。
6. **上传保留子目录**：`read_csv("CAUSALITY/resume.csv")` 这类项目相对路径开箱即用。

**语料三：Gelman/Hill/Vehtari《Regression and Other Stories》官方示例 + TidyTuesday 社区作品集（jkaupp）**：

- ROS 14 个非 Stan 脚本全部跑通：`births.R` 动画式循环出图 **2000 步 + 138 张图**、`Coop/riverbay.R` 295 步 + 46 图、bootstrap/中心极限模拟均正常。
- TidyTuesday 8 个真实分析作品：6 个干净通过（含 20 秒级网络数据加载），其余因 ggstream/ggpattern 等小众包缺失而由"出错后继续"兜底记录。
- 由此修复：**错误步的上限缓冲**（错误可越过步数帽但至多 +50，防连锁报错撑爆 trace）；**图形面板只渲染最近 12 张**（"… N earlier plots hidden"），防动画循环的百余张图压垮 DOM。
- 环境备注：macOS 本机 Rscript 下个别脚本触发 QuartzBitmap 写盘报错、magick 包在进程退出时已知 segfault——均为本机设备层现象，webR canvas 路径不受影响。

**第四轮：面向非专业读者的代码理解层**（`lib/explain.ts`，纯前端规则引擎，零额外运行时开销）：

- 逐步白话解释条（中英双语），由运行时事实拼装：动词语义（70+ 常用函数词典：dplyr 动词/建模/检验/读数/绘图/抽样）+ 行列增减 + 新列名 + 变量创建/更新（含类型与形状）+ 循环迭代位置 + 报错说明（"该语句被跳过，继续执行"）。
- 管道六边形节点增加行列增减徽标（−28r 红 / +1c 绿），不读代码即可看懂每环效果。
- 数据表新出现的列表头以绿色高亮。
- 实测（dplyr 示例 9 步）：每步解释均具体到真实数字，如 "summarise() — 把每组压缩成一行统计结果 · 59 → 32 行（−27），新列：n, mean_bmi"。

**观察到但未实现的改进候选**：函数遮蔽提示（错误信息旁标注 "select 可能被 MASS 覆盖，试 dplyr::select"）；片段依赖自动检测（提示"该变量可能来自上一次运行，开启保留工作区"）。

## 五、已知限制（当前版本）

- 自定义函数体内不逐行步进（见 3.1.5）。
- `points()`/`lines()` 对已有图的追加、`par(mfrow)` 子图不计为独立图形步。
- 字符串里的 `|>` 可能让该行的管道拆解标注偏移（不影响执行结果）。
- 无 wasm 构建的 CRAN 包无法安装（给出明确报错）。
- 用户代码不配对的 `sink()` 可能让该步 stdout 归属错乱。
